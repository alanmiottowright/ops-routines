For [[email-triage]]: mark read + archive **every** notification generated by a Google document (Docs, Sheets, Slides, Forms, Drive — shares, comments, replies, mentions, action items; `comments-noreply@docs.google.com`, `drive-shares-noreply@google.com`). Report as an aggregate count, no per-item summaries.

**Single exception:** the comment @-mentions Alan's own address (`@alan.wright@rocket.chat`) AND asks him to do, decide, answer, or review something. Then keep in inbox, leave UNREAD, categorize Action Needed. Still no tracking label — the action happens in the doc, so an email label can never resolve; it goes on the "Actions waiting in other systems" checklist instead.

**Why:** Alan receives these because he is a doc *collaborator*, which is not the same as being tagged — the most common misfire. Worked example he gave: "Entrada de Faturas / Invoices A Pagar", where Karine Dourado posts a recurring "Bom dia!! Saldos atualizados." comment @-tagging and assigning `guilherme.barbosa@novagestao.digital`. Alan is only on the To: line. It kept returning to his inbox as each daily reply landed.

**How to apply:** Archive even when someone else is @-tagged or the item is "Assigned to <other>"; when Alan is tagged for visibility/FYI only; on recurring status-update comment threads regardless of reply count; on resolved comments, replies after Alan already answered in-doc, and activity digests; and when Alan was tagged earlier but a later comment shows it was answered or reassigned. When ambiguous, archive — the notifications repeat, so a miss comes back, while a false keep clutters the inbox daily. See [[email-triage-tracker-design]].
